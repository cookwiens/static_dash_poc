# LDCPH Respiratory Surveillance Dashboard — Static Site

A mobile-first static dashboard for weekly ED visit rates and wastewater surveillance
trends (COVID-19, Influenza, RSV), branded for Lawrence-Douglas County Public Health and
built to be pushed straight to GitHub Pages — no build step, no server, no framework.

## Why this approach

| Option | Interactive? | Works offline / no CDN? | Effort to maintain |
|---|---|---|---|
| **Chart.js (used here)** | Yes — hover tooltips, legend toggle, pinch/scroll on mobile | Yes, `chart.min.js` is vendored in `assets/js/vendor/` | Low — data lives in plain JSON, decoupled from rendering |
| Bokeh | Yes | Only if you bundle `bokeh.min.js` yourself; otherwise needs CDN + version pinning between the Python package and the JS bundle | Medium — regenerate & re-embed HTML/JS blobs each data refresh |
| matplotlib/seaborn (SVG or PNG) | No (static image) | Yes | Lowest, but no tooltips and images must be regenerated (and re-sized for mobile) every refresh |

Since your notebook already handles all the downloading/transforming, this template
keeps that Python work focused purely on **producing two small JSON files**
(`assets/data/ed_visits.json` and `assets/data/wastewater.json`). All charting logic
lives in `assets/js/main.js` using Chart.js, so the site is fully static, fast, and
touch-friendly, and you never have to regenerate/embed a chart library's HTML output.

If you'd still rather render with Bokeh, Plotly, or matplotlib, see the "Alternatives"
section at the bottom — the HTML/CSS shell is written so any of them can slot into the
same `<div class="chart-wrap">` containers.

## Folder structure

```
ldcph-site/
├── index.html                     # the whole site (single page, anchor-linked sections)
├── assets/
│   ├── css/styles.css             # brand colors + responsive layout
│   ├── js/
│   │   ├── main.js                # fetches JSON, builds all 6 charts, mobile nav toggle
│   │   └── vendor/chart.min.js    # Chart.js v3.9.1, vendored (no CDN dependency)
│   ├── data/
│   │   ├── ed_visits.json         # <-- regenerated by your notebook each refresh
│   │   └── wastewater.json        # <-- regenerated by your notebook each refresh
│   └── img/
│       ├── logo.svg               # PLACEHOLDER — replace with your real logo
│       └── favicon.svg
├── scripts/generate_sample_data.py   # produces the demo JSON you see now
└── notebook/                          # data-prep notebook template (see below)
```

## Brand colors used

Defined as CSS variables in `assets/css/styles.css` (`:root`), so you can retint anything
site-wide by editing one place.

- Logo colors: `#f3711b` (orange, primary accent), `#707a83` (slate), `#a0ddfc` (sky),
  `#1776bc` (blue, primary)
- Pathogen color-coding (consistent across **both** the ED chart and the wastewater
  chart for each pathogen, so users learn "orange = COVID" once and it holds everywhere):
  - **COVID-19** → orange family (`#f3711b` current / `#ff9d72` prior year)
  - **Influenza** → blue family (`#1776bc` current / `#a0ddfc` prior year)
  - **RSV** → teal/green family (`#48a69a` current / `#80c586` prior year)
- Header/nav/footer use the darker extended navy (`#2d4a76`) for contrast and text
  readability (`#575757`) for secondary copy.

## Replacing the demo data with yours

1. Swap the two loader functions in `notebook/` (or wherever you paste that code into
   your existing notebook) to pull your real ED visit and wastewater data.
2. **Read the "counts vs. rates" note in the notebook before wiring up ED prior-year
   data** — if your prior year is only available as raw counts (not a rate), don't
   overlay it directly against a current-year rate without converting or re-labeling;
   the notebook explains your options.
3. Run the notebook; it writes `assets/data/ed_visits.json` and
   `assets/data/wastewater.json`.
4. Refresh the page locally (see below) to confirm it looks right, then commit + push.

### JSON schema quick reference

`ed_visits.json`
```json
{
  "generated": "2026-09-04",
  "unit": "Rate per 100,000 ED visits",
  "pathogens": [
    {
      "key": "covid",
      "label": "COVID-19",
      "current_label": "Current (Sep 2025–Sep 2026)",
      "previous_label": "Prior year (Sep 2024–2025)",
      "week_labels": ["Sep 8", "Sep 15", "..."],
      "current":  [7.4, 8.7, "... (null allowed for missing weeks)"],
      "previous": [6.1, 6.9, "..."]
    }
  ]
}
```

`wastewater.json`
```json
{
  "generated": "2026-09-04",
  "unit": "Viral gene copies / L (7-day trend)",
  "pathogens": [
    {
      "key": "covid",
      "label": "COVID-19",
      "points": [{ "date": "2026-03-02", "value": 812 }, { "date": "2026-03-06", "value": 940 }]
    }
  ]
}
```
`week_labels`/`current`/`previous` must all be the same length per pathogen.
`points` can have irregular/uneven date spacing — the chart plots true time-proportional
spacing (no fixed weekly grid required), which matters since wastewater sampling isn't
always exactly weekly.

## Previewing locally

No build tools needed — just serve the folder (opening `index.html` directly via
`file://` will fail because `fetch()` can't load local JSON files under that protocol):

```bash
cd ldcph-site
python -m http.server 8000
# visit http://localhost:8000
```

## Deploying to GitHub Pages

1. Create (or reuse) a GitHub repo, e.g. `ldcph/respiratory-dashboard`.
2. Push the contents of this `ldcph-site/` folder to the repo root (or to a `/docs`
   folder — either works, you just need to point Pages at the right one).
3. In the repo: **Settings → Pages → Build and deployment → Source: Deploy from a
   branch**. Choose `main` and `/ (root)` (or `/docs`). Save.
4. GitHub will publish at `https://<org-or-user>.github.io/<repo-name>/` within a minute
   or two. If you have a custom domain, add it via **Settings → Pages → Custom domain**
   and add the corresponding `CNAME` DNS record.
5. Every time you refresh data: re-run the notebook, `git add` the two JSON files,
   commit, push — Pages redeploys automatically.

## Customizing

- **Replace the logo**: drop your real logo file in as `assets/img/logo.svg` (or `.png` —
  just update the `<img src>` in `index.html`), and regenerate `favicon.svg` from it if
  you want a matching browser tab icon.
- **Add/remove a pathogen**: duplicate one `<section>` block in `index.html`, add a new
  entry to `PATHOGEN_META` in `main.js`, and add matching colors as CSS variables.
- **Change the units/labels**: edit the `unit`, `current_label`, `previous_label` fields
  in the JSON — no code changes needed.
- **Agency contact / links**: edit the `<footer>` block in `index.html`.

## Alternatives if you'd rather render in Python

- **matplotlib/seaborn**: render each chart to SVG (`fig.savefig("chart.svg")`) — SVGs
  scale crisply on any screen with just `img { max-width: 100%; }` (already in
  `styles.css`). Simplest path, but you lose hover tooltips and must regenerate one image
  file per chart per refresh.
- **Bokeh**: use `bokeh.embed.components(fig)` to get a `<script>`/`<div>` pair per chart
  and paste them into `index.html` in place of the `<canvas>` elements. Set
  `sizing_mode="stretch_width"` on each figure for mobile responsiveness, and vendor
  `bokeh.min.js`/`bokeh-widgets.min.js` locally (matching your installed `bokeh` Python
  version exactly) if you don't want a CDN dependency.

Either would slot into the same page structure/CSS grid — only the chart-rendering step
changes.
