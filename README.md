# LDCPH Respiratory Surveillance Dashboard — Static Site

A mobile-first static dashboard for weekly ED visit rates and wastewater surveillance
trends (COVID-19, Influenza, RSV), branded for Lawrence-Douglas County Public Health and
built to be pushed straight to GitHub Pages — no build step, no server, no framework.

## Why this approach

| Option | Interactive? | Works offline / no CDN? | Effort to maintain |
|---|---|---|---|
| **Chart.js (used here)** | Yes — hover tooltips, legend toggle, pinch/scroll on mobile | Yes, `chart.min.js` is vendored in `assets/js/vendor/` | Low — data lives in plain JSON, decoupled from rendering |
| Bokeh | Yes | Only if you bundle `bokeh.min.js` yourself; otherwise needs CDN + version pinning between the Python package and the JS bundle | Medium — regenerate & re-embed HTML/JS blobs each data refresh |
| matplotlib/seaborn (SVG or PNG) | No (static image) | Yes | Lowest, but no tooltips and images must be regenerated (and re-sized for mobile) every refresh |

Since your notebook already handles all the downloading/transforming, this template
keeps that Python work focused purely on **producing three small JSON files**
(`assets/data/ed_visits.json`, `assets/data/wastewater.json`, and
`assets/data/narrative.json`). All charting logic lives in `assets/js/main.js` using
Chart.js, so the site is fully static, fast, and touch-friendly.

## What changed from the first version

- **"At a Glance" stat tiles removed.** In their place is a **Current Situation**
  section — a single narrative block you write directly in the notebook.
- **Narrative supports limited HTML formatting.** You can use `<b>`, `<i>`, `<hr>`, and
  `<br>` (plus `<strong>`, `<em>`, `<u>`, `<p>` as equivalents) when writing the summary.
  Anything else is stripped by a small built-in sanitizer before it's rendered — see
  "Narrative formatting & sanitization" below.
- **ED and wastewater charts share one x-axis per pathogen.** Both charts for a given
  pathogen (e.g., COVID-19 ED visits + COVID-19 wastewater) now use the exact same date
  range and the exact same tick marks, even though ED points fall weekly on Sundays and
  wastewater points fall on irregular days (~2-3/week). See "Shared x-axis" below.

## Brand colors used

Defined as CSS variables in `assets/css/styles.css` (`:root`), so you can retint anything
site-wide by editing one place.

- Logo colors: `#f3711b` (orange, primary accent), `#707a83` (slate), `#a0ddfc` (sky),
  `#1776bc` (blue, primary)
- Pathogen color-coding (consistent across **both** the ED chart and the wastewater
  chart for each pathogen, so users learn "orange = COVID" once and it holds everywhere):
  - **COVID-19** → orange family (`#f3711b` current / `#ff9d72` prior year)
  - **Influenza** → blue family (`#1776bc` current / `#a0ddfc` prior year)
  - **RSV** → teal/green family (`#48a69a` current / `#80c586` prior year)
- Header/nav/footer use the darker extended navy (`#2d4a76`) for contrast and text
  readability (`#575757`) for secondary copy.

## Narrative formatting & sanitization

`narrative.json` holds one field, `html`, which you write directly in the notebook as a
plain Python string (see Step 3 in `notebook/notebook_data_prep.ipynb`). Before it's
inserted into the page, `main.js` runs it through `sanitizeNarrativeHtml()`, a dependency-
free whitelist sanitizer that:

- **Keeps** `<b>`, `<i>`, `<hr>`, `<br>`, `<strong>`, `<em>`, `<u>`, `<p>` — but strips any
  attributes on them (so `<b onclick="...">` becomes plain `<b>`).
- **Unwraps** any other tag (e.g., a stray `<div>` or `<a>`) — keeps the text/content
  inside, discards the tag itself.
- **Removes entirely** `<script>` and `<style>` tags, including their contents.

This means you can paste in text with occasional formatting mistakes (e.g., copy-pasted
from Word) without it breaking the page or introducing a script-injection risk — anything
outside the allow-list is neutralized. If you want to allow more tags (e.g., `<a>` for
links), edit `ALLOWED_NARRATIVE_TAGS` at the top of the narrative section in
`assets/js/main.js`.

## Shared x-axis between ED and wastewater charts

Each pathogen's ED chart and wastewater chart automatically compute a **shared date
range and shared tick marks** (`computeSharedXAxis()` in `main.js`), based on the actual
calendar dates in both series combined — not on week/sample index. Concretely:

- The ED chart plots on the actual Sunday date of each week (no more generic "week 1,
  week 2..." labels).
- The wastewater chart plots on the actual sample date, which can fall on any day and
  needn't be evenly spaced (2-3 samples/week is expected and handled fine).
- Both charts for a pathogen get the same axis `min`, `max`, and the same fixed
  `stepSize` (chosen automatically to keep ~5-7 readable ticks), so the tick labels line
  up exactly whether you're comparing the two charts side-by-side on desktop or stacked
  on mobile.

**For this to work well with your real data**, make sure the ED and wastewater series you
feed in cover roughly the same overall period — the axis range is driven by the min/max
date found across *both* series, so if one series has a much longer history than the
other, the shorter one will look "compressed" into one end of a wider axis.

## Replacing the demo data with yours

1. Swap the two loader functions in `notebook/notebook_data_prep.ipynb` to pull your real
   ED visit and wastewater data.
2. **Read the "counts vs. rates" note in the notebook before wiring up ED prior-year
   data** — if your prior year is only available as raw counts (not a rate), don't
   overlay it directly against a current-year rate without converting or re-labeling;
   the notebook explains your options.
3. Write your **Current Situation** narrative directly into the `NARRATIVE_HTML` string
   in Step 3 of the notebook.
4. Run the notebook; it writes `ed_visits.json`, `wastewater.json`, and `narrative.json`
   into `assets/data/`.
5. Refresh the page locally (see below) to confirm it looks right, then commit + push.

### JSON schema quick reference

`ed_visits.json`
```json
{
  "generated": "2026-03-01",
  "unit": "Rate per 100,000 ED visits",
  "pathogens": [
    {
      "key": "covid",
      "label": "COVID-19",
      "current_label": "Current (Mar 2025–Mar 2026)",
      "previous_label": "Prior year (Mar 2024–2025)",
      "dates":    ["2025-03-09", "2025-03-16", "..."],
      "current":  [8.5, 7.3, "... (null allowed for missing/future weeks)"],
      "previous": [6.1, 6.9, "..."]
    }
  ]
}
```
`dates` must be the actual Sunday of each week (ISO `YYYY-MM-DD`), and `current`/
`previous`/`dates` must all be the same length per pathogen.

`wastewater.json`
```json
{
  "generated": "2026-03-01",
  "unit": "Viral gene copies / L (7-day trend)",
  "pathogens": [
    {
      "key": "covid",
      "label": "COVID-19",
      "points": [{ "date": "2025-03-09", "value": 524 }, { "date": "2025-03-11", "value": 616 }]
    }
  ]
}
```
`points` can have irregular/uneven date spacing — the chart plots true time-proportional
spacing (no fixed weekly grid required), which matters since wastewater sampling isn't
always exactly weekly.

`narrative.json`
```json
{
  "generated": "2026-03-01",
  "html": "<b>Respiratory illness activity remains at seasonal-expected levels.</b><br>Influenza is trending <i>slightly upward</i>.<hr>More detail here."
}
```

## Previewing locally

No build tools needed — just serve the folder (opening `index.html` directly via
`file://` will fail because `fetch()` can't load local JSON files under that protocol):

```bash
cd ldcph-site
python -m http.server 8000
# visit http://localhost:8000
```

## Deploying to GitHub Pages

1. Create (or reuse) a GitHub repo, e.g. `ldcph/respiratory-dashboard`.
2. Push the contents of this `ldcph-site/` folder to the repo root (or to a `/docs`
   folder — either works, you just need to point Pages at the right one).
3. In the repo: **Settings → Pages → Build and deployment → Source: Deploy from a
   branch**. Choose `main` and `/ (root)` (or `/docs`). Save.
4. GitHub will publish at `https://<org-or-user>.github.io/<repo-name>/` within a minute
   or two. If you have a custom domain, add it via **Settings → Pages → Custom domain**
   and add the corresponding `CNAME` DNS record.
5. Every time you refresh data: re-run the notebook, `git add` the three JSON files,
   commit, push — Pages redeploys automatically.

## Customizing

- **Replace the logo**: drop your real logo file in as `assets/img/logo.svg` (or `.png` —
  just update the `<img src>` in `index.html`), and regenerate `favicon.svg` from it if
  you want a matching browser tab icon.
- **Add/remove a pathogen**: duplicate one `<section>` block in `index.html`, add a new
  entry to `PATHOGEN_META` in `main.js`, and add matching colors as CSS variables.
- **Change the units/labels**: edit the `unit`, `current_label`, `previous_label` fields
  in the JSON — no code changes needed.
- **Agency contact / links**: edit the `<footer>` block in `index.html`.

## Alternatives if you'd rather render in Python

- **matplotlib/seaborn**: render each chart to SVG (`fig.savefig("chart.svg")`) — SVGs
  scale crisply on any screen with just `img { max-width: 100%; }` (already in
  `styles.css`). Simplest path, but you lose hover tooltips and must regenerate one image
  file per chart per refresh, and you'd need to compute/apply the shared axis range
  yourself (e.g., via `ax.set_xlim(...)` with matching bounds and tick locators).
- **Bokeh**: use `bokeh.embed.components(fig)` to get a `<script>`/`<div>` pair per chart
  and paste them into `index.html` in place of the `<canvas>` elements. Set
  `sizing_mode="stretch_width"` on each figure for mobile responsiveness, and share the
  x-range across a pathogen's two figures with `fig2.x_range = fig1.x_range`. Vendor
  `bokeh.min.js`/`bokeh-widgets.min.js` locally (matching your installed `bokeh` Python
  version exactly) if you don't want a CDN dependency.

Either would slot into the same page structure/CSS grid — only the chart-rendering step
changes.
